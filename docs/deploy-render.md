# Deploying Trajectory on Render

Render runs the API and web app from the repository's `Dockerfile`. Render has no Oracle hosting, so the
database is an **Oracle Autonomous Database** on Oracle Cloud's *Always Free* tier, reached over TLS.

| Piece | Where | Cost |
|---|---|---|
| API + web app | Render web service (`render.yaml`) | Free (sleeps after 15 min idle) or Starter $7/mo |
| Database | Oracle Autonomous Database, Always Free | Free |
| ML service (optional) | Render private service | Starter $7/mo |
| App installers | GitHub Release assets | Free |

Allow about 30–45 minutes the first time.

---

## 1. Create the Oracle database (Oracle Cloud)

1. Sign up at <https://www.oracle.com/cloud/free/> (needs a card for identity checks; Always Free resources are not charged).
   Pick a **home region** close to the Render region you will use (for example *India West (Mumbai)* or
   *Singapore* with Render's `singapore`).
2. Menu → **Oracle Database → Autonomous Database → Create Autonomous Database**:
   - Display name / database name: `trajectorydb`
   - Workload type: **Transaction Processing**
   - **Always Free**: on
   - Database version: 19c or 23ai (both work)
   - Set the **ADMIN password** and note it down
   - Network access: **Secure access from everywhere**
   - Leave **Require mutual TLS (mTLS) authentication** ticked (this guide uses the wallet)
3. When it shows *Available*, open **Database actions → SQL** and create the application user:

   ```sql
   CREATE USER trajectory IDENTIFIED BY "Choose-A-Strong-Passw0rd";
   GRANT CREATE SESSION, CREATE TABLE, CREATE SEQUENCE, CREATE VIEW TO trajectory;
   ALTER USER trajectory QUOTA UNLIMITED ON DATA;
   ```

   The API creates all tables itself on first start.
4. Back on the database page: **Database connection → Download wallet** (type *Instance wallet*). Set a
   **wallet password** and note it. Unzip the file; you need two files from it:
   `ewallet.pem` and `tnsnames.ora`.
5. Open `tnsnames.ora` and note the service names. Use the one ending in **`_high`**, for example
   `trajectorydb_high`.

> Always Free databases stop after 7 days without connections and are deleted after 90 days stopped.
> A deployed app that is used keeps it alive; otherwise start it again from the console.

## 2. Generate the secrets

Run once on your computer and save the output somewhere safe (a password manager):

```bash
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```

This is `DATA_ENCRYPTION_KEY`. **Keep a copy outside Render** — without it uploaded resumes cannot be
decrypted. (`JWT_SECRET` and `JWT_REFRESH_SECRET` are generated by Render automatically.)

## 3. Publish the app installers (optional)

Render's disk is wiped on every deploy, so the APK and Windows installer are hosted on GitHub instead:

1. GitHub → the **Trajectory** repository → **Releases → Draft a new release**, tag `v1.0.0`.
2. Drag in `backend/downloads/trajectory-android-1.0.apk` and
   `backend/downloads/trajectory-desktop-windows-1.0.0.exe`, then **Publish release**.
3. Right-click each asset → *Copy link address*. Join the two links with a comma — that is `DOWNLOAD_URLS`.

Settings → "Get the apps" lists them automatically.

## 4. Create the Render service from the Blueprint

1. Sign in at <https://dashboard.render.com> with GitHub and allow access to the **Trajectory** repository.
2. **New + → Blueprint**, choose the repository. Render reads `render.yaml` and shows the `trajectory`
   web service.
3. Fill in the values it asks for:

   | Variable | Value |
   |---|---|
   | `ORACLE_PASSWORD` | the `trajectory` user's password from step 1.3 |
   | `ORACLE_CONNECTION_STRING` | the `_high` name, e.g. `trajectorydb_high` |
   | `ORACLE_WALLET_DIR` | `/etc/secrets` |
   | `ORACLE_WALLET_PASSWORD` | the wallet password from step 1.4 |
   | `DATA_ENCRYPTION_KEY` | the value from step 2 |
   | `FRONTEND_URL` | `https://trajectory.onrender.com` (adjust after the first deploy if Render picks another name) |
   | `ADMIN_EMAIL` / `ADMIN_PASSWORD` | the admin account to create (password: 8+ characters) |
   | `DOWNLOAD_URLS` | from step 3, or leave empty |

4. Click **Apply**. The first build takes 5–10 minutes.
5. While it builds, open the service → **Environment → Secret Files** and add two files, pasting the
   contents from the unzipped wallet:
   - filename `ewallet.pem`
   - filename `tnsnames.ora`

   Save; Render redeploys with the files at `/etc/secrets/`.

## 5. Check it

- **Logs** should show the migration files (`→ 001_create_schema.sql …`), `Seeded 42 questions`,
  `Admin account created: <email>` and `Trajectory API listening`.
- Open `https://<your-service>.onrender.com/api/health` → `{"status":"ok", …}`.
- Open the site, sign in with the admin account and check **Admin → Questions** shows 42 questions.

If `FRONTEND_URL` differs from the real address, update it under **Environment** — the API only accepts
browser requests from that origin (comma-separate several, e.g. the onrender.com address and a custom domain).

## 6. Custom domain (optional)

Service → **Settings → Custom Domains → Add**, then create the DNS record Render shows. HTTPS is
automatic. Update `FRONTEND_URL` to the new address.

## 7. Updating

Every push to `main` redeploys automatically (`autoDeploy: true`). New database migrations run on start.

## Optional extras

- **Always-on:** change `plan: free` to `starter` in `render.yaml` (free instances take ~1 minute to wake).
- **AI interview scoring:** set `LLM_PROVIDER=openai` and add `OPENAI_API_KEY`.
- **ML service:** uncomment the `trajectory-ml` block in `render.yaml` and add the `ML_SERVICE_URL`
  entry shown there. Without it, recommendations use the rule-based engine.
- **Backups:** Autonomous Database takes automatic daily backups (60-day retention), so `npm run db:backup`
  is not needed there.

## Without a wallet (TLS only)

If you prefer not to upload wallet files: on the database page, **Network → Access control list → Edit**,
add Render's outbound IP ranges (service → **Connect → Outbound**), then untick **Require mutual TLS**.
Copy the **TLS** connection string from **Database connection** (the long `(description=…)` value) into
`ORACLE_CONNECTION_STRING`, and leave `ORACLE_WALLET_DIR` and `ORACLE_WALLET_PASSWORD` empty.

## Troubleshooting

| Symptom in logs | Fix |
|---|---|
| `DATA_ENCRYPTION_KEY is required in production` | Set it under Environment. |
| `NJS-…` / `ORA-12506` / connection timeouts | Check the wallet Secret Files and password, or the ACL when using TLS only. |
| `ORA-01017` | Wrong `ORACLE_USER` / `ORACLE_PASSWORD`. |
| `ORA-01950: no privileges on tablespace` | Run `ALTER USER trajectory QUOTA UNLIMITED ON DATA;` |
| Sign-in or sign-up fails with a CORS / network error | `FRONTEND_URL` must exactly match the address in the browser (scheme, host, no trailing slash). |
| Out of memory on the free plan | Lower `EXEC_MAX_CONCURRENCY` to `1`, or move to Starter. |
